# 老款小爱音箱 Pro（LX06）音频链路深度分析与优化记录

本文档记录了对老款**小米小爱音箱 Pro（LX06，固件 1.94.13）**原厂语音引擎与硬件音频链路的实测分析，以及本项目针对 LX06 做的底层适配原理。

---

## 1. LX06 硬件音频布局（与新款 OH2P 的关键差异）

查看 LX06 `/etc/asound.conf` 与 `/proc/asound/card0/pcm3c/sub0/hw_params`，并对 `hw:0,3` 直接录制 48 kHz 8 声道原始 `S32_LE` 数据验证，同时核对原厂 `/usr/lib/libxaudio_engine.so` 中的 `AudioRecord_Read`：

| 项目 | 新款小米智能音箱 Pro（OH2P） | 老款小米小爱音箱 Pro（LX06） |
| --- | --- | --- |
| 硬件录音节点 | `hw:0,3`（`noop` / `dsnoop`） | `hw:0,3`（`noop` / `dsnoop`，`period_size=384, buffer_size=6144`） |
| 硬件采样率 / 格式 | 16 kHz / 4 ch | **48 kHz / 8 ch / `S32_LE`** |
| 声道分配 | `ch0~ch2` 麦克风，`ch3` 功放回采 | **`ch0~ch5` 6 颗环形实体麦**，`ch6` 预留，**`ch7` 功放回采（高 16 位）** |
| 麦克风数据位宽 | 32-bit 容器 | 24-bit PDM 有效数据落在低 24 位（原厂右移 `>> 14` 提取） |
| 播放 PCM 名称 | `Playback` | 仅存在 `default` / `notify` / `bluetooth`（无 `Playback`） |
| 系统默认重采样器 | — | `defaults.pcm.rate_converter "speexrate_medium"` |
| `/data` 可用闪存 | 较宽裕 | 仅约 **9 MB**（RAM `/tmp` 约 120 MB） |
| 原生唤醒日志 | `wakeup.sh: asrstart/asrend`、`send real_wakeup event` | **无 `wakeup.sh`**；由 `mipns-xiaomi` (`real wakeup--`) 与 `mico_aivs_lab` (`WAKEUP_REAL:`) 写 `/tmp/log/messages` |

## 2. 导致原版直接移植到 LX06 拾音极差的 4 个致命根因

### 根因 1：声道错配——把 4 号实体麦当成“喇叭回声”，WebRTC 把人声自己抵消掉了
- 上游代码按 OH2P 4 声道布局，将 `ch0` 作为拾音输入、将 **`ch3`** 喂入 `aec_->AnalyzeReverseStream()` 作为喇叭回采参考。
- 在 LX06 上，`ch3` 其实是 **4 号实体麦克风**，它和 `ch0` 录到的是同一份人声！
- WebRTC `EchoCancellation::kHighSuppression` 误将说话人（尤其是远场与儿童）自己的声音识别为极强回声并实时相减抵消，导致实测上行语音中位数 `rms_p50` 仅剩 `7~16`（约 `-66 dBFS`）。
- **修复**：改为按 8 声道采集并提取真正的功放回采通道 **`ch7`**（`>> 16`），彻底终结人声自消。

### 根因 2：ALSA `speexrate_medium` 的 16-bit 预截断毁掉远场弱声
- 当 `arecord` 请求 `-r 16000` 时，ALSA `plug` 自动插入 `speexrate_medium` 执行 `48 kHz -> 16 kHz` 重采样。
- `speexrate_medium` 内部以 `S16_LE` 运算，重采样前先把 `S32_LE` 粗暴右移 16 位截断（实测低 16 位全为 `0x0000`）。
- LX06 的 24-bit PDM 麦克风远场弱声主要落在低位（静音样本典型值 `~0x000ab1b6`），截断后仅剩 4~6 bit 阶梯量化噪声。
- **修复**（对照原厂 `AudioRecord_Read` 思路）：
  - 直接以硬件原生 **`48000 Hz / 8 ch / S32_LE`**（`--buffer-size 6144 --period-size 768`）采集，完全绕开 ALSA 重采样；
  - 在 `Lx06Decimator48To16` 中用 24-bit 浮点精度先执行 **31 阶对称 Kaiser 低通 FIR（`fc = 7000 Hz`，12 kHz 以上阻带衰减 > 81 dB）** 3:1 降采样到 16 kHz，再按 `s32_shift`（`14` 对齐原厂，`13` 额外 `+6 dB` 利于短句/儿童）输出，并串联 50 Hz 去直流高通滤波；
  - `ch7` 功放回采走同一套 31 阶线性相位 FIR，确保麦克风与回采参考 **0 样本群延迟对齐**。

### 根因 3：KWS `KwsAgc` 慢攻击削波，把第一声“豆”直接削废
- 安静待机时 `KwsAgc` 增益停在 `15.85× (+24 dB)`；原有实现采用级联两层 `0.9/0.1` 慢平滑（攻击时间 ~100~200 ms）且无瞬时峰值上限。
- 从安静突然喊“豆包豆包”时，前 ~100 ms（整整第一声 **“豆”**）被放大到 5 万~10 万直接硬削波成方波，导致第一遍喊几乎必漏，连喊二三遍等增益掉下来才醒。
- **修复**：加入 **每 10 ms 帧前瞻峰值天花板（`26000 / frame_peak`）+ 20 ms 极速压限 + 250 ms 平滑恢复 + `tanh` 软拐点**，保证第一声起音零削波，同时保留远场 +24 dB 增益。

### 根因 4：单一 8 音素词表容错低 + 播放无回声消除 + 管道阻塞丢帧
- **双层唤醒词匹配**：保留 4 种 `āo/ao` 混合 8 音素整句（`#0.02` 兜底远场轻声），同时新增 6 种常见自然/方言/儿童声调 4 音素半词（`@豆包半`，`#0.08~0.12`），1.8 秒内命中 2 次（间隔 ≥ 140 ms）即触发“豆包豆包”，兼顾快喊、带停顿喊、口音/儿童声调且不增加单字误唤醒。
- **6 麦全开波束成形**：将 `DownmixToMono` 扩展至全部 6 颗麦（`max_lag = ±4` 覆盖 7.4 cm 环阵 360°），增加静音/弱相关帧防抖（稳在 `lag = 0` 避免辅音高频相消），并同时用于唤醒和半双工云端上行。
- **播放中打断（`SubbandAec`）**：喇叭出声时自动启用纯线性多抽头子带回声消除（使用固定 `lag = 0` 6 麦环阵均值与 `ch7` 回采），实测消除外放回声 **23~30 dB** 而不压低叠加喊出的“豆包豆包”；喇叭静音时自动休眠零开销。
- **零 `overrun` 异步采集**：48 kHz 8ch 原始码率 1.536 MB/s，将 `arecord` pipe 扩容至 1 MB 并拆分异步分发线程，配合 `nice -n -10` 运行，实测 `overrun_lines = 0`。

## 3. 原生小爱同学共存与联动（LX06 专属适配）

- 轮询 `/tmp/log/messages`（30 ms 间隔）监听 LX06 原厂 `mipns-xiaomi`（`real wakeup--`）与 `mico_aivs_lab`（`WAKEUP_REAL:`）真实唤醒事件。
- 在豆包播报、思考或等待期间喊 **“小爱同学”** 时，豆包会在 ~80 ms 内掐断播报、取消云端回复、平滑释放灯环（不误熄灭小爱的蓝色聆听灯环）并退出豆包模式；3 秒内去重防重入，2 秒后恢复待命以便随时再喊“豆包豆包”。
